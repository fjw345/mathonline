# 北交大数学在线刷题平台 · 产品设计文档

> 版本说明（2026-11-12）：规则、接口与页面地图按当前程序修订；线框保留早期信息层级示意，不代表像素级实现。首期排期及试跑数字仅作历史背景，后续 AI 与生存模式按第 6、7 节及[后续开发计划](../后续开发计划（10-15周）.md)推进。

## 1. 设计目标与原则

### 1.1 设计目标

对应 [需求分析文档 · 1.4](需求分析文档.md#14-业务目标与衡量指标) 的四条业务目标：

| 目标 | 设计上的可验证落点 |
| --- | --- |
| G1 真题可检索 | 筛选器**始终可见**且状态可分享（URL 同步）；筛选结果计数**实时可见** |
| G2 练习有状态 | 每道题的"我做过/做对过/做错过"在列表、详情、练习三处**视觉一致** |
| G3 习惯可持续 | 每日一题拥有**独立入口 + 独立卡片形态**，打卡状态一眼可读 |
| G4 题解有沉淀 | 答案区把"官方答案 / 平台整理解析 / 用户题解"**三类内容分区呈现并标注来源** |

### 1.2 五条设计原则

1. **先作答，后核对**：登录后提交作答或点击“不会”才解锁答案，由后端校验；解锁后可收起或展开，再次进入或重做默认折叠（AC-06.1～AC-06.3）。
2. **状态不靠用户记忆**：做过什么、错在哪里，由系统在任何需要的位置主动展示，而不是让用户自己回想（对应"不统计重做次数"的简化心智）。
3. **一题一屏**：做题页面只承载"这道题"，不塞入推荐、排行榜等干扰元素。
4. **判分结果如实标注**：自动判分就是自动判分，自评就是自评，**绝不把用户的判断包装成系统的客观结论**。
5. **手机优先的数学排版**：公式必须可读、可横向滚动而不撑破布局；这是数学类产品最容易翻车的地方。

### 2.4 核心用户旅程

**旅程 A：新用户 15 分钟闭环（对应 MVP 判定标准）**

| 步骤 | 用户动作 | 系统响应 / 结果 |
| --- | --- | --- |
| 1 | 从首页进入每日一题 | 显示筛选与手动打开入口，未登录提示登录 |
| 2 | 邮箱注册 → 验证邮件 → 登录 | 普通登录按 `next` 回跳；当前验证邮件回调进入 `/me`，再手动回到每日一题 |
| 3 | 登录后选择范围并点击 [打开今日题目] | 分配并展示当天固定题目 |
| 4 | 作答 → 交卷 | 选择题自动判分；填空、解答题进入待自评 |
| 5 | 完成自动判分或自评 | 当天分配题目完成后自动打卡，对错均可；答案解锁后可查看 |
| 6 | 阅读解析 | 当前版本曾做对时可发布题解，再次进入页面答案默认折叠 |

**旅程 B：错题复习**

| 步骤 | 用户动作 | 系统响应 / 结果 |
| --- | --- | --- |
| 1 | 我的学习 → 错题 | 列出当前待复习题目，包含答错与点击“不会”的题 |
| 2 | 选中一道题 → 进入详情 → 重做 | 复用同一作答入口 |
| 3 | 做对 | 更新当前作答结果，仍保留在错题清单，直到用户主动移出 |
| 4 | 确认已掌握 | 点击“已掌握，移出错题”，只改变清单状态，不改写作答历史 |

**旅程 C：题解发布与审核**

| 步骤 | 角色 | 动作 / 结果 |
| --- | --- | --- |
| 1 | 注册用户（曾做对） | 题目详情 → 答案区 → [发布题解] → 编辑（Markdown + LaTeX + 图片） |
| 2 | 注册用户 | 提交后状态为「待审核」，**仅自己可见**并带"审核中"标识 |
| 3 | 审核人员 | 后台 → 待审核队列 → 查看 → [通过] |
| 4 | 系统 | 题解公开可见，并通知作者「你的题解已通过审核」 |
| 5 | 系统 | 后续被点赞/评论 → 作者收到站内通知（**自己的操作不通知自己**） |

## 3. 界面草图与交互说明

### 3.0 草图约定

- 线框为**低保真**，只表达信息层级与交互位置，不表达最终视觉。
- `●` 表示当前选中态，`○` 表示未选中；`[按钮]` 表示可点击控件；`▾` 表示下拉；`⌄ / ⌃` 表示折叠/展开。
- 每张草图后**必须**配交互说明表；表内条目用 `AC-*` 指向前文验收标准，用 `UC-*` 指向用例。

### 3.8 响应式适配与状态清单

**断点**

| 断点 | 范围 | 布局策略 |
| --- | --- | --- |
| 手机 | ≤ 640 px（导航断点） | 顶部导航；内容单列；答案与作答上下排列，避免横向溢出 |
| 平板 | 中等宽度 | 按可用宽度折叠内容，具体组件断点以样式为准 |
| 桌面 | 宽屏 | 左侧导航；作答与可收起参考答案栏并排；筛选器在内容区展示 |

**公式与图片的移动端处理（NFR-04 的重点）**

- 独立公式块宽度超出容器时，**容器内横向滚动**，绝不横向撑破整页；
- 行内公式允许换行断点，避免长公式把整行推出去；
- 题目配图按容器宽度等比缩放，点击进入全屏查看（支持双指缩放）。

**每个页面的四类必备状态**

| 状态 | 表现 |
| --- | --- |
| 加载中 | 骨架屏（列表）/ 按钮 loading（提交），**不使用全屏遮罩** |
| 空结果 | 说明"为什么空" + 给出下一步动作（清空筛选 / 去练习 / 去答题） |
| 提交失败 | 保留用户已填内容与已选选项，提供 [重试]；**不静默失败、不清空输入** |
| 无权限 / 未登录 | 提示原因 + 明确入口（去登录 / 去验证邮箱），登录后回跳原位置 |

### 4.2 数据模型支撑（已有基线）

本节补充题目提交后的可选判题建议，与原有答案查看和用户自评流程衔接，对应需求 FR-26。

### 6.1 入口与结果呈现

- 填空题和解答题提交后，在作答结果区域提供「获取判题建议」入口，由用户主动触发；选择题继续使用现有确定性判分。
- 请求处理中显示加载状态，并暂时禁用重复触发；不影响查看标准答案和解析。
- 返回结果以「模型辅助建议」单独展示，状态为「建议正确」「建议错误」或「无法判断」，附简要理由；不替代系统判分，也不覆盖用户自评。
- 用户仍按原流程选择自评结果。模型建议与自评分别呈现，自评结果继续作为个人做题状态、打卡和题解发布资格的依据。

### 6.2 失败处理与数据边界

- 模型超时、不可用、拒答或返回内容无法解析时，显示「暂时无法提供判题建议」，保留已提交作答，并继续提供标准答案、解析及自评入口。
- 判题请求仅包含完成本次判断所需的题目内容、标准答案或评分要点、本次作答；不发送用户账号 ID、邮箱等身份信息。
- 辅助建议不得触发每日打卡、改变答案解锁状态或授予题解发布资格。服务接入、数据留存和调用限制需在实现前完成评审。

### 6.3 v1.2 修改说明

本轮在原作答与自评界面增加可选的模型建议展示及异常回退，覆盖 FR-26、UC-22 和 AC-26.1 至 AC-26.5。该功能列为 P2 规划；当前版本不将模型建议视为已实现能力。

## 7. 生存模式（后续迭代）

### 7.1 开始挑战

登录用户选择题库标签、年份和题型后，页面展示候选题数、题型及判题方式。候选题不足 10 道时提示扩大范围；已有未完成挑战时提供「继续挑战」和「结束本轮」。开局后固定本轮范围、题目顺序和规则版本。

### 7.2 作答与生命

页面展示当前生命、已通过题数、题目及「提交答案」「不会」操作。初始生命为 8，上限为 10；选择题和填空题正确 +0.5、错误或不会 -1，解答题正确 +1.5、错误或不会 -0.5。这些数值用于试玩，后续可调整。生命归零或本轮题目全部完成时结束挑战。

选择题按正确选项判分，填空题与解答题由 AI 判题。提交后显示「判题中」，结果确定前不改变生命或通过题数；结算后以文字和数值展示判定结果、生命变化及当前生命，再提供「下一题」。提交被受理或选择「不会」后可查看参考答案和解析，但不能自行改判以获得计榜成绩。手机端题目与答案上下排列，长公式可横向滚动。

### 7.3 异常与恢复

离开页面后可继续原挑战。判题失败、服务不可用或需要复核时保留作答和生命，不按错误处理；题目作废时不扣血。对结果有异议可申请复核，复核期间暂停挑战并暂不计榜，确认误判后本轮不计榜。重复提交或重试只结算一次。

### 7.4 成绩与排行榜

结束页展示结束原因、通过题数、正确率、剩余生命、题库范围及是否计榜，并提供查看本轮题目、再来一轮和返回题库的入口。周榜、月榜和总榜按预设题库范围及规则版本分别展示，以通过题数为主要成绩；未解决判题或复核的挑战不计榜。

生存模式不产生每日打卡；按当前题目版本判定正确后可获得题解发布资格。普通练习继续使用原有判分和自评流程，第 6 节的模型辅助建议不直接改变普通练习结果。

### 7.5 v1.2 修改说明

依据生存模式设计方案，补充开局、作答、生命结算、异常恢复和排行榜的界面流程；生存模式仍为后续迭代。
