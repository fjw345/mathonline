# 需求分析与产品设计文档修改说明

## 一、修改目的与范围

主要是根据已确认的业务规则与当前程序，修正文档中不一致、过时或容易引起误解的表述，明确区分历史方案、当前功能与后续规划。

- [需求分析文档](需求分析文档.md)
- [产品设计文档](产品设计文档.md)

## 二、需求分析文档的主要修改

| 修改内容 | 修订后的表述 |
| --- | --- |
| 题库展示与维护 | 公开题面和参考答案使用文字版，原始截图保留供维护核对；有效题目默认发布，缺漏材料进入待补队列，用户反馈后管理员复核，不要求逐题预审。 |
| 筛选范围 | 保留题库类别标签、年份、题型和关键词，不设置难度评级，不恢复组别、来源、科目筛选。 |
| 参考答案权限 | 登录后提交作答或点击“不会”才解锁答案，由后端校验；再次进入、刷新或重做默认折叠，已解锁权限保留。 |
| 判分与打卡 | 选择题按选项判分，多选不受选项顺序影响；普通填空、解答题使用自评。当天分配的每日题完成判分或自评后可打卡，对错均可；“不会”及待自评不算完成。 |
| 错题复习 | 答错或点击“不会”加入错题；做对不自动移出。用户确认掌握后可主动移出，保留作答历史与答案权限，再次答错或“不会”时重新加入。 |
| 题目版本与题解资格 | 区分题目版本、作答修订与题解版本；发布题解须曾做对当前题目版本，专用文字回填不递增题目版本。 |
| 已有功能覆盖 | 补充论坛、更新信箱、邀请资料、题目反馈与公告管理用例（UC-24～UC-28），避免仍将已实现功能列为待开发。 |
| 验收与历史数据 | 同步相关验收条件；保留问卷与早期抽取数字，但标明历史背景，不作为当前题库规模、线上验证结果或当前数据结构的证明。 |

## 三、产品设计文档的主要修改

| 修改内容 | 修订后的表述 |
| --- | --- |
| 页面地图与导航 | 按当前路由修正页面入口，区分页内标签与独立页面；补充论坛、信箱和邀请入口，说明桌面左侧导航、手机顶部导航。 |
| 每日一题流程 | 先登录、选择范围，再手动打开当天题目；已分配题目同账号同日固定，重新进入时手动继续。修正注册、验证、登录与打开题目的步骤顺序。 |
| 随机练习流程 | 应用筛选后切换范围，保留对应题目及草稿，支持下一题；不将切页或刷新描述为自动换题。 |
| 作答与答案交互 | 同步提交、“不会”、自评和答案折叠状态；提交后预览已提交作答，参考答案使用可收起右栏，手机上下排列。 |
| 个人中心与管理页 | 同步错题移出和昵称设置等当前能力；将头像上传、公开个人页、独立审核日志查询等未交付内容标为待完善。 |
| 接口与数据模型 | 修正路由、接口和表字段映射；上传按当前后端中转流程描述，不再将签名直传及确认接口写成已实现能力；区分早期抽取模型与当前运行库。 |
| 排期与验收 | 保留首期排期作为历史背景，勾选不代表本次验收；修正“必须做对才能打卡”等过时口径，后续安排关联 10–15 周开发计划。 |
