# 更新信箱与邀请资料

本次新增站内更新信箱和邀请资料页。实现支持本地 SQLite 与云端 Supabase，云端需要新增迁移和两个服务端环境变量；不用重新导入题库。

## 上线步骤

1. 在原 Supabase 项目打开 **SQL Editor → New query**。
2. 在仓库打开 [20261108121156_announcements_invites.sql](../supabase/migrations/20261108121156_announcements_invites.sql)，复制**全部 SQL 内容**到编辑器，执行一次。不要把文件路径当作 SQL 输入，也不要重跑旧迁移。成功后会新增公告、已读、邀请码和邀请绑定四张表及相关函数，RLS 已包含在脚本里。
3. 在 **Vercel → 项目 → Settings → Environment Variables** 添加以下变量，作用于准备部署的环境：

   | 变量 | 填写内容 |
   | --- | --- |
   | `RESOURCE_DOWNLOAD_URL` | 本次提供的完整夸克分享链接，包括 `?pwd=...` |
   | `RESOURCE_EXTRACTION_CODE` | 该分享的提取码 |

   两者仅供 Python 服务端使用，不加 `VITE_` 前缀。实际分享地址不写入前端源码或公开配置示例。之后更换网盘资料只需修改这两个变量并重新部署。

4. 部署包含本次改动的代码。如果 Vercel 已自动构建，添加变量后再执行一次 **Redeploy**。迁移未执行时，新页面会明确提示需要更新数据库；不会假报发布或绑定成功。
5. 登录管理员账号，进入 **管理 → 更新公告**，发布一条更新。在账号附近点 **更新信箱** 检查显示。使用不同的已验证邮箱账号绑定邀请人的邀请码，累计两人后在邀请人页面点击 **刷新进度 → 查看下载链接**。

本轮没有在生产 Supabase 执行 SQL，也没有验证线上部署。迁移会创建新表，不改题目、作答或原有邀请数据（此前没有此功能）。若执行时报表已存在，先核对是否已经成功执行过本迁移，不要删除线上表重试。

## 本地使用

当前电脑的 `.env` 已配置用户本次提供的夸克地址和提取码。重启本地服务后生效；`.env` 不提交 Git。其他维护者可参照 `.env.example` 填写同名变量。

本地启动时自动创建新表，不需要执行 PostgreSQL SQL。资料地址为空时，邀请进度和绑定仍可使用，下载按钮会提示资料尚未准备好。不能使用 `D:\resource.zip` 作为公网地址；本轮采用夸克分享，不上传本地资料包。

## 使用规则

- **更新信箱 `/mailbox`**：登录用户查看已发布更新，按原始创建时间倒序，每页 12 条。展开即标记该账号已读，编辑后再次标为未读；内容按纯文本显示，支持换行。
- **管理页**：只有管理员能发布、编辑、保存草稿、隐藏或重新发布更新。审核员没有公告管理权限。并发编辑时旧版本会被拒绝，需刷新后再操作。
- **邀请与资料 `/invites`**：每个账号有固定邀请码，可复制邀请码或邀请链接；链接会把邀请码带到登录/注册后的页面，用户手动确认绑定。
- **允许注册后填写**：现有账号也能绑定，但每个账号最多绑定一位邀请人，绑定后不能更换；不能绑定自己。重复提交同一码不会重复计数。
- **云端邮箱验证**：被邀请账号必须先验证邮箱再绑定，绑定成功立即计入邀请人数；未验证时接口拒绝绑定。本地版没有邮件验证流程。
- **邀请两人解锁**：仅计算直接绑定，不计算朋友的朋友。下载接口每次独立检查人数，管理员也不例外。未登录或未达人数时不返回网盘链接及提取码。
- **外部分享边界**：网站控制谁能获得分享链接；拿到夸克链接后可在站外转发，网站无法控制网盘之外的传播。更换或撤销资料需要同时在夸克管理分享。

## 验证与维护

已完成隔离 SQLite 环境的后端完整回归（80 项）；在邀请人数统计改为 SQL 聚合后，再次通过该功能 6 项测试。前端类型检查和生产构建通过。真实浏览器验证了邀请链接注册回跳、注册后绑定、两人解锁、未达人数拒绝、信箱已读隔离及 320 / 375 / 412 / 768 / 1280 像素无横向溢出，未发生页面脚本错误；这不是安卓真机或线上验收。

新增迁移也已在独立 PGlite PostgreSQL 环境执行验证，包括浏览器角色禁止直接访问、唯一绑定、人数阈值、公告版本及已读状态；尚未在托管 Supabase 执行。相关本地验收产物在 Git 忽略的 `output/` 中。

本次新增前端页面与组件、入口文件的格式检查，以及所改 Python 文件的 Ruff 检查通过。全仓前端格式检查仍报告 9 个文件的既有排版问题（含已有 Admin 页面），本次未对这些文件整体重排。

四张新表开启 RLS，撤销 `anon` / `authenticated` 及公开角色权限，仅 `service_role` 访问。相关函数使用 `SECURITY INVOKER`、固定空 `search_path`；用户身份、邮箱验证和管理员权限由后端检查。邀请码绑定使用唯一约束与事务锁防止并发改绑；公告更新使用版本检查防止旧页面覆盖新内容。私人接口保持 `no-store`。

本功能不提供发送邮件、群发通知、邀请排行榜、账号反作弊识别或后台解绑入口。需要调整绑定关系时另行制定受控维护流程，不能在浏览器放开数据库权限。
