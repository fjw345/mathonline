# AI 自动核对答案（判分）

本页记录 2026-11-10 加入的「AI 自动核对答案」功能：填空题与解答题在提交后由服务端自动判分，选择题沿用既有的显式选项比对。面向维护者，全文区分**已实现**、**需执行迁移**与**本轮未验证**三种状态。

相关代码与数据：`backend/grading.py`（判分引擎）、`backend/config.py`（模型配置）、`backend/main.py`（判分端点）、`backend/schema.sql` 与 `supabase/migrations/20261110000000_ai_grading.sql`（新增两表）、`frontend/src/views/Problem.vue` 与 `frontend/src/types.ts`（提交后自动调用与展示）。

## 1. 现状与覆盖范围

| 题型 | 判分方式 | 对应实现 |
| --- | --- | --- |
| 选择题 | 沿用既有显式选项比对，不调用模型；判分入口对选择题直接拒绝，调用方不会把它送进 AI 判分 | `grading.judge` 开头按题型分流 |
| 填空题 | 归一化 + 数值容差算法优先；算法只在“双方都是数值且不接近”时判错，其余不匹配交模型兜底 | `normalize`、`algorithmic_verdict`、`_judge_blank` |
| 解答题（大题） | 模型依据 `problem_answers.text` 文字详解生成得分点，再逐点判分；全部得分点命中才算正确，否则记错 | `rubric_for`、`generate_rubric`、`_judge_solution` |

- **填空题算法口径（已实现）**：`normalize` 做全角转半角（NFKC）、去掉 `$`、去掉 `\left` / `\right`、`\dfrac` 改写为 `\frac`、压缩空白、去掉句末标点（`。．.，,；;：:！!？?、`）。`algorithmic_verdict` 先把参考答案按 `；`、`;`、`，`、`,` 与“或”拆成多个候选，逐个比较：归一化后完全一致即判对；双方都能解析成数值时按 `rel_tol=abs_tol=1e-9` 比较，支持 `1/2` 与 `0.5`、`\frac{1}{2}` 与 `0.5` 互通。只有当“至少有一个候选与作答形成了数值比较、但都不接近”时才返回 `incorrect`；其余情况（例如参考 `x=2` 而作答 `2`、中文答案写法不同）返回空结论，交模型兜底。
- **AI 不可用时的行为（已实现）**：模型未配置、请求失败、输出不可解析、得分点缺失或缺判，统一抛 `GradingUnavailable`，由 `judge` 吞掉并返回空结论，调用方保持“待自检”，既不报错也不假装判过。
- **纯图片作答的边界**：判分只读提交里的文字。提交只有图片引用、没有文字时，判分入口直接返回空结论，保持待自检，不会送模型，也不为此接入视觉模型。
- **文字详解覆盖**：得分点固定依据数据库中的 `problem_answers.text`，不看图片。按仓库清单统计，1,868 道题的题干与答案都有文字、没有图片回退题（见 AGENT.md §4 与[文字版题面与答案](text-bank.md)）；线上实时数量以数据库为准，本页不另行断言。
- **安全边界**：不执行用户输入的代码，不做表达式求值。数值比较只走正则匹配的数字与分数，模型调用只做文本问答。

## 2. 服务端配置

模型调用统一走 OpenAI 兼容的 `POST {AI_BASE_URL}/chat/completions`，唯一调用点是 `backend/grading.py` 的 `_chat`。

| 变量 | 含义 | 缺省 |
| --- | --- | --- |
| `AI_BASE_URL` | 兼容接口的基地址，末尾 `/` 自动去掉；实际请求路径为 `{基地址}/chat/completions` | 空 |
| `AI_API_KEY` | 调用密钥，仅以 `Authorization: Bearer` 头在服务端使用 | 空 |
| `AI_MODEL` | 模型名，同时写入 `problem_rubrics.model` 与 `problem_grading.model` | 空 |
| `AI_TIMEOUT` | 单次模型请求超时秒数，按浮点解析 | `30` |

- 后端由 `AI_ENABLED` 判断可用性：`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 三项全部非空才启用，不需要另外设置开关。示例项见仓库根目录 `.env.example`。
- **密钥只放服务端环境变量**：不要写入前端代码、前端构建产物、README、`.env.example` 或任何提交记录，也不要在日志和报错里回显。前端的 `available` / `reason` 只承载“能不能判、为什么不能判”，不带凭证与基地址。
- **未配置时的降级行为（已实现）**：判分端点返回 `available=false`，前端静默保持“待自检”，提交与草稿照常保存，不给用户报错。填空题在算法能判定时仍然会判（算法不依赖模型），只是模型兜底这一段不可用。

## 3. 判分流程

1. **提交作答**：用户提交文字和/或图片，进度记录产生一次新的修订号；提交仍然先按既有权限规则解锁参考答案。
2. **前端自动调用判分端点**：`Problem.vue` 只在“本次结果仍为待自检、未过期、尚未有 AI 快照、题型不是选择题”时调用一次，并按“题目 + 修订号”去重，避免重复请求。
3. **端点校验**：`POST /api/v1/me/problems/{pid}/grade`，请求体 `{"problem_version": int, "revision": int}`。
4. **题型分流**：选择题由既有显式选项比对负责；填空题先走算法，算法无把握且模型可用才调模型；解答题先取得分点再逐点判分。
5. **得分点缓存**：解答题首次判分时，模型依据 `problem_answers.text` 生成得分点（提示要求 3 到 6 条），落库到 `problem_rubrics`；同一题后续判分直接复用缓存，不再调用模型生成。
6. **逐点判分**：把学生作答与得分点列表交给模型，要求逐个给出命中与理由；只要有一个得分点没被判到，整题按不可用处理。全部命中记正确，否则记错误（分数为命中条数 / 总条数）。
7. **结果与分数落库**：AI 原始判分快照写入 `problem_grading`（结论、分数、满分、逐点明细、模型名、题目版本、时间），每人每题一份。
8. **展示**：响应把更新后的题目对象返回，`problem.progress.ai_grading` 携带 `{result, score, max_score, points:[{point,hit,note}], model, created_at}`；前端据此展示得分点命中情况与分数，并保留“自检修正”入口。

端点契约（本页以此为准；实现位于 `backend/main.py`，本文不展开其内部细节）：

| 状态 | 含义 |
| --- | --- |
| `200` | `{"available": bool, "reason": str, "problem": <题目对象>}`。`available=false` 表示判分不可用（未配置密钥 / 调用失败 / 缺少文字详解 / 迁移未执行），此时保持“待自检”，不算错误 |
| `400` | 选择题已由既有自动判分处理，或题目缺少文字详解 |
| `403` | 尚未提交作答 |
| `409` | 题目已更新（版本不符）或该修订已经判过分 |
| `429` | 判分过于频繁（阈值 20 次/分钟） |

## 4. 数据表说明

本次新增两张表，均在 `backend/schema.sql`（本地 SQLite）与 `supabase/migrations/20261110000000_ai_grading.sql`（云端）中定义，迁移为纯新增，不改动既有表与策略。

| 表 | 职责 | 关键字段 |
| --- | --- | --- |
| `problem_rubrics` | 题目级得分点缓存，详解文本不变时复用同一份 | `problem_id`（主键，外键 `problems.id`）、`answer_hash`（生成得分点所用详解文本的 SHA-256，缓存失效依据）、`points`（jsonb）、`model`、`created_at` |
| `problem_grading` | 每人每题的 AI 原始判分快照 | `id`（主键，取值 `{user_id}:{problem_id}`）、`user_id`、`problem_id`、`result`、`score`、`max_score`、`points`（jsonb 逐点明细）、`model`、`problem_version`、`created_at`，并带唯一约束 `(user_id, problem_id)` 与 `problem_id` 索引 |

**为什么 AI 快照要和 `user_problem_progress` 分开**：

- 进度表记录的是“当前学习状态”，会被后续提交、重做和自检修正覆盖；AI 快照记录的是“模型当时判了什么”，一旦写入就是历史。
- 用户用“自检修正”改判时，只应改进度表的当前结论，不能顺手把模型的原始结论改写掉。分表存放让两边各管一件事：改判不覆盖快照，快照也不反过来约束改判。
- 快照里保留 `model` 与 `problem_version`，事后可以追出“哪个模型的哪一版结论”，题目改版后不会和当前版本混在一起。
- 得分点单独放进 `problem_rubrics`，是因为它是题目维度的复用数据（不含用户），与“每人每题”的快照维度不同，混在一起会重复存储并放大调用成本。

## 5. 上线步骤

1. **执行迁移**（需执行迁移）：按既有云端迁移流程执行 `supabase/migrations/20261110000000_ai_grading.sql`。它创建两张表、开启 RLS、撤销 `public` / `anon` / `authenticated` 的全部权限、只授权 `service_role`，并 `notify pgrst` 让 PostgREST 立即看到新表。执行前先确认目标环境，执行后核对两张表存在且只有 `service_role` 有权限。
2. **配置模型密钥**：在部署环境（不是仓库、不是前端）设置 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`，按需调整 `AI_TIMEOUT`；改完需要重新部署或重启 API。
3. **不重跑题库导入**：本次没有题库数据结构变化，文字详解与清单都不动。按仓库规则，导入、迁移、部署是不同操作，只执行本轮明确授权的迁移。
4. **未执行迁移时的行为（已实现，本轮未做线上验证）**：判分读写新表失败会被当作“判分不可用”，端点返回 `available=false`，前端保持“待自检”，不假报成功、不写入伪造结论。迁移补齐后无需改动数据即可直接生效。
5. **冒烟**：登录后对一道填空题和一道解答题各提交一次，确认解答题出现得分点明细；若 `available=false`，先看 `reason`，再依次排查密钥、接口连通性、`problem_answers.text` 是否为空、迁移是否执行。

## 6. 成本与限流

- **得分点只生成一次**：`problem_rubrics` 按题目缓存，命中缓存后不再调用模型生成；详解文本不变时一题只付一次生成成本。命中判断以 `problem_rubrics.answer_hash` 为准：它与当前详解文本的 SHA-256 一致、且 `points` 能解析出非空得分点才算命中；详解文本一改摘要就不再匹配，下次判分自动按新详解重新生成并写回缓存，不需要人工删缓存行。
- **每次提交一次判分调用**：填空题模型兜底一次调用；解答题在得分点已缓存时是一次逐点判分调用（首次那道题是“生成得分点 + 逐点判分”两次）。算法能判定的填空题不产生调用。
- **限流**：判分端点限 20 次/分钟，超出返回 `429`。前端已按“题目 + 修订号”去重，正常翻页和重进不会重复触发。
- **输出稳定性**：请求体固定 `temperature: 0`，并要求模型只返回 JSON 对象；`_chat` 会剥掉 Markdown 代码围栏再解析，解析失败按不可用处理而不是猜结论。
- **超时与截断**：单次请求超时由 `AI_TIMEOUT`（默认 30 秒）控制；题面与详解各截断到 4,000 字符、作答截断到 4,000 字符、参考答案超过 80 字符就不走算法、模型返回的得分点超过 15 条按不可用处理（不截断）、单条得分点最多 200 字符。这些上限用于压住单次调用的输入规模。

## 7. 已知边界与风险

- **模型可能误判**：判分是模型依据参考答案与详解给出的结论，不是数学证明。用户可以用“自检修正”改判，改判只动进度表，AI 原始快照按设计保留。
- **得分点缺判即整题降级**：只要模型漏判任意一个得分点，代码就抛不可用，整题回到“待自检”，不会拿部分结果冒充结论；宁可少判，不假报错误。
- **严格口径的代价**：解答题必须全部得分点命中才算正确，部分正确的作答会被记为错误并进入错题栏。这是本轮明确选定的口径，不是缺陷；但它意味着“思路对、步骤缺”会被判错。
- **算法判错的边界**：算法只在双方都是数值且不接近时判错，所以像参考 `x=2`、作答 `2` 这类会被交给模型；模型不可用时保持待自检，而不是回落到“算错”。
- **纯图片作答不判**：没有文字的提交一律待自检，不会为了图片接入视觉模型。
- **得分点缓存按详解文本自动失效**：`problem_rubrics` 只按 `problem_id` 存一份，记录里没有 `problem_version`，但带有 `answer_hash`（详解文本的 SHA-256）。详解文本改版后摘要不再匹配，下次判分会按新详解重新生成得分点，无需人工删缓存行；只有详解文本未变时才复用旧得分点。
- **判分与改判的先后**：`problem_grading` 每人每题唯一，重复判分由端点用 `409` 拦下；自检修正之后仍以用户结论作为当前学习状态。

## 8. 验证方法

不需要真实密钥也能自查的部分：

1. **算法判分的纯函数用例（本轮已在本地执行通过）**：在隔离临时库路径下导入 `backend.grading`，直接断言 `algorithmic_verdict` 的三种分支——`0.5` 对 `1/2` 判对、`2` 对 `3` 判错、参考 `x=2` 而作答 `2` 返回无法判定。命令见 AGENT.md §6。该命令不配置 `AI_*`、不调用模型、不连接 Supabase；导入模块会初始化所指定的隔离临时库的本地表结构（AGENT.md §6 里 pytest 命令用的是同类临时路径），属于可丢弃的离线产物。同一组断言也可覆盖 `normalize` 的去 `$` 与 `\dfrac` 改写。
2. **判分端点返回 `available=false` 的降级路径**：本地启动服务时把 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 三项留空，登录后提交一道“算法判不出、需要模型兜底”的填空题，或任意一道解答题。期望：端点返回 200 且 `available=false`、`reason` 给出原因，`progress.result` 保持 `pending`，页面显示“待自检”，参考答案和提交记录都不受影响。本轮未做这条 HTTP 端到端验证，需在本地服务上补做。
3. **迁移缺失时的降级**：在未执行迁移的环境重复上一步，期望同样是 `available=false` 与“待自检”，且不出现“判分成功”的假象。
4. **不要求执行的检查**：本文档不要求跑前端构建，也不要求连 Supabase；涉及真实模型的调用需要密钥，本轮未验证。
