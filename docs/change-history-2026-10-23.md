## 2. 从初始需求到当前规则

| 主题 | 早期设想或曾出现的问题 | 后续确认与当前约定 |
| --- | --- | --- |
| 题面处理 | 从 PDF 抽取文本、还原公式后组织题库，实际效率和可用性不足 | 以原卷拆分截图展示题目、参考答案和解析；保留有序图片引用与原始路径，不以 OCR 或文本化为上线前提 |
| 开发起点 | 多类试卷并行规划 | 先基于已拆分的全国大学生数学竞赛非数学类做本地 MVP，再扩充考研与北交期末 |
| 填空题判分 | 标准答案、数值误差或表达式比较 | MVP 与解答题一样提交后自检；选择题依据显式正确选项自动判分 |
| 查看答案 | 早期 PDF 允许游客主动展开，做对后默认展开 | 登录且成功提交或点击“不会”才解锁；“不会”在提交左侧；重进、刷新、重做默认折叠 |
| “不会”的结果 | 早期只解锁答案，没有进入错题栏 | 2026-10-23 起解锁并加入错题栏，保留草稿，不伪造作答或改写已有判分、不打卡、不获得题解发布资格 |
| 错题掌握 | 曾做错的题始终保留，不能主动移出 | 2026-10-23 起错题栏支持“已掌握，移出错题”；保留历史，做对不自动移出；再次答错或点击“不会”重新加入 |
| 每日一题 | 进入页面即分题 | 先选范围，再手动打开；同账号同日已分配题目固定，重新进入手动继续 |
| 随机练习 | 离开再进入会换题并丢失未提交回答 | 按账号和已应用筛选恢复题目、文字、图片引用、选项及题解编辑草稿；用户主动换题才重新抽取 |
| 连续练习 | 缺少易发现的下一题入口 | 在随机练习顶部和作答区增加“下一题”；候选多于一道时避免紧邻重复 |
| 公开筛选 | 组别、难度、来源、科目等多维条件 | 只保留题库类别标签、年份、题型、关键词；不设难度评级；来源、组别、科目保留作后台元数据 |
| 标签范围 | 曾要求只保留“全国大学生数学竞赛·非数” | 这是首批阶段范围；之后考研和期末新增题库已明确获准，类别随实际可见题目扩充，不能永久硬编码为一个标签 |
| 题库审核 | 早期抽取数据先草稿、逐题复核后发布 | 完整且判分配置有效的题目默认发布；用户反馈后管理员核查。缺图、答案不明等已知问题素材不强行发布 |
| 社区审核 | 容易与题库默认发布混用 | 用户题解和评论仍须审核；私人作答不自动公开；普通用户只看已通过内容 |
| 题解资格 | 曾做对即可发布 | 以当前题目版本的曾做对为依据；自检正确明确标注自评；同版本后来做错不抹去资格，修题后不能沿用旧版本资格 |
| 管理员 | 首个账号在云端没有管理员权限 | 本地首次注册有初始化管理员逻辑；云端注册不自动提权，由维护流程设置 `profiles.role` |
| 数据维护 | 新增和更换题目可能影响历史 | 稳定 ID、版本递增、导入幂等、保护网页人工修订；新清单未列出的旧题不删除 |

做题记录保留每人每题的当前状态及“曾做对/曾做错”等依据，不统计重做次数。填空题和解答题提交后先待自评，完成自评才更新对错并判定每日打卡；答错也可完成当日打卡。

### 部署过程中解决和澄清的事项

- Supabase SQL Editor 执行的是迁移文件里的 SQL 内容，文件路径 `supabase/migrations/...sql` 本身不是 SQL 命令。
- 业务表启用 RLS，浏览器访问收紧；服务端凭证可以绕过 RLS，身份、归属、答案和管理权限仍由后端检查。
- Vercel 构建曾因 `pyproject.toml` 缺少 `[project]` 失败，后补项目元数据并固定 Python 3.12；另处理锁文件和函数包体积问题。
- `APP_ORIGIN` 对应实际页面的完整 origin；认证邮件、回调和密码重置地址需与部署环境匹配，修改环境变量后重新部署。
- 部署区域已由用户调整；后续性能优化继续基于接口和图片链路，不能仅凭区域变化认定速度达标。
- GitHub 代码推送与部署、SQL 结构迁移、题库数据导入是三种更新。仅新增题库数据且无需改应用时，不要求重跑旧迁移或重新部署。
- 管理页曾出现一直加载及“服务响应异常”；迭代中补充异常处理、超时、分页和批量关联读取。具体故障仍应以报错和请求证据定位，不认定所有加载慢均由图片造成。

### 当前已落地的加载优化

- 题库列表在数据层按年份、题型、标签筛选和分页；关键词仍有服务端字面筛选路径，不宣称所有查询都完全下推数据库。
- 来源、图片、答案及用户状态按请求批量读取，减少逐题查询；管理列表分页，避免一次读取全部题目及大批图片。
- 公开类别信息采用实例内 30 秒缓存，不共用私人状态或答案权限缓存。
- 首页已发布题干批量签发 300 秒 Storage 链接，浏览器直接读取；失败回退原媒体接口。答案及私人作答不采用该公开列表优化。
- 预览进入视口附近才创建图片，使用浏览器懒加载和异步解码；多张图片依原顺序呈现。
- 普通前端请求默认 20 秒超时、上传 60 秒，避免异常请求永久显示加载中。

以上是实现策略，不代表已完成特定校园网或移动网络下的性能验收。签名链接在有效期内不因下架立即撤销；目前也没有单独的缩略图生成流水线。

## 8. 2026-10-24：错题复习清单

本轮用户要求：点击“不会”的题目也应进入错题栏，错题可以主动移出，表示已经掌握。

- 点击“不会”解锁参考答案并加入错题栏；没有作答记录时仍不创建提交，不打卡，不授予做对资格，保留未提交草稿。
- 原有自动判错和自评错误也进入错题栏。历史错题及过去点过“不会”的题会在数据库更新时补入，重复事件不生成重复条目。
- 在“我的学习 → 错题”点击“已掌握，移出错题”，仅改变该账号的错题清单；不会删除历史作答、曾做错标记、已获答案权限或当前版本做对资格。
- 做对不自动移出，用户确认掌握后主动移出；以后再次答错或点击“不会”会重新加入。页数、列表数量和“待复习错题”统计同步更新。
- 新增独立表 `user_mistakes`。错误提交或“不会”写入时，由数据库触发器在同一事务维护错题状态；标记掌握不修改 `user_problem_progress` 或 `answer_access`。
